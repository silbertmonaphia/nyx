## 5. Absorbed resume-contract fixes (user-approved scope, 2026-10-14)

> Not part of the sweeper's design; these are pre-existing defects the §4.4 full-suite gate uncovered. Both production bugs were found by the DB-gated tests that CI never runs (no `TEST_ASYNC_PG_DSN` in `ci.yml` → they self-skip there).

- [x] 5.1 `executor_node` resume-aware skip: a step whose id already has an entry in `state["step_outputs"]` (rehydrated from the checkpoint) is skipped — no re-execution, no re-emitted frames. This is `agent-python-service` req 11 compliance ("completed nodes are NOT re-executed"); the executor never implemented it (the pinning test's docstring had documented the gap). **Verified** — `test_run_resume.py::test_executor_skips_completed_steps_on_resume` (0 tool calls on resume).
- [x] 5.2 `run_agent_stream` pure-resume input — **real production bug**: langgraph treats a non-None `astream` input as a state UPDATE, so resuming with the freshly-built `new_state()` clobbered every checkpointed channel (plan, step_outputs, events_so_far) and made the planner AND completed steps re-run — token + tool double-spend on every resume. Even `{}` schedules from the entrypoint (verified empirically); the fix drives `astream(None)` when a usable checkpoint exists (continues from its pending nodes; on an already-END graph it yields the final snapshot without raising), falling back to the fresh state only when no checkpoint exists (crash before the first node). **Verified** — `test_run_resume.py::test_planner_does_not_rerun_on_resume` (call_count exactly 3); END-state edge exercised directly (no exception; final snapshot yielded). **Review correction (2026-10-14)**: those tests pin langgraph's semantics but NOT `run_agent_stream`'s choice of input — the wiring is now pinned at the endpoint level in `test_resume_inside_window_still_resumes` (bind-count zero delta + tools zero delta + exactly one remaining step-2 llm call on resume); see §6.2.
- [x] 5.3 Test-harness hardening for the same failure class: (a) `test_run_resume.py` now patches settings BEFORE building the app/lifespan — the old inside-the-lifespan patch let phase 1 run on the ambient `.env` DSN while phase 2 used the test DSN (two different databases → the "resume" read empty state); its `_patch_settings` helper also rebinds `agent.main.get_settings`, because `agent.main`'s from-import copies the function reference at import time and can capture an earlier test's active monkeypatch. (b) `test_graph_persistence.py`'s `_StubLlm` regained the planner's structured-output `bind()` path (stale since `agent-planner-structured`, which had made it emit `planner_failed`). **Verified** — both files green in isolation and in full-suite ordering; touched modules clean under `ruff check` (ClassVar annotations, unquoted annotations, builtin `TimeoutError`; pre-existing lint debt in unrelated files left alone — ruff is not CI-enforced).
