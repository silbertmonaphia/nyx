## 2. Normalizer + chunker

The Markdown implementation must recognise headings at every level, keep fenced code blocks as one block, keep tables as table blocks, and exclude front matter from every block's text. Verify: unit tests with golden fixtures covering nested headings, a fenced code block, a table, front matter, and a file with no headings.
- [ ] 2.2 Implement `backend/internal/kb/chunker.go`: group blocks by heading path, pack them to the target token budget under the hard cap, never split a table (split an oversized table by rows with the header repeated), never split a fenced code block, keep a below-minimum section rather than dropping it, and never let a chunk span two heading paths. The chunk's embedded text is the relative path, then the heading path, then the body; the body alone is stored as the chunk content. Verify: unit tests asserting — no chunk exceeds the hard cap; no chunk carries two heading paths; an oversized table produces several chunks each starting with the header row; a code block is never split; a one-line section survives with its heading; the embedded text starts with the path-and-heading prefix while the stored content does not contain it.
- [ ] 2.3 Implement the token estimator used by the chunker (a deterministic approximation — the corpus is Chinese-dominant, so a character-class-aware estimate, not a whitespace word count) and pin it with unit tests covering Chinese, mixed Chinese/English, and code. Verify: unit tests for the estimator's monotonicity and its behaviour on the three scripts.

## 3. Connector + indexer

- [ ] 3.1 Implement `backend/internal/kb/connector.go`: walk a source root, honour the ignore rules (hidden files and directories, `.git`, `.DS_Store`), enforce the max-file-size, max-file-count and max-depth limits, and resolve every candidate's real path — refusing any file whose resolved path leaves the source root. Verify: unit tests for the ignore rules, for each limit, and for a symlink that escapes the root.
- [ ] 3.2 Implement `backend/internal/kb/indexer.go`: for each candidate file, hash the raw bytes; skip the document when the hash matches the stored one and make no embedding call; on a changed hash, delete the document's chunks and re-chunk and re-embed; on a file that disappeared, delete its chunks and mark the document absent. A file whose type is not Markdown SHALL be skipped with a recorded reason and SHALL NOT abort the scan. Verify: unit tests over a temporary tree — unchanged file makes zero embedding calls (assert with a counting stub embedder), changed file replaces its chunks, deleted file's chunks are removed, an unsupported file is skipped and the rest of the tree still indexes.
- [ ] 3.3 Implement the two-phase write: write the chunks with an empty embedding first, then fill them through the claim query (`FOR UPDATE SKIP LOCKED`). On an embedding failure, the document SHALL end `pending` with its chunks already stored, and a later fill SHALL complete it WITHOUT re-parsing the source. Verify: unit test that fails the embedder on the first pass and asserts the second pass issues no parse call and completes the document.
- [ ] 3.4 Implement the explicit index trigger over the caller's visible sources (their private sources plus the shared source) and the bounded lazy catch-up — a detached context, a per-user once-guard, a bounded batch — mirroring `rag.Service.BackfillOnce`. Verify: unit tests for the trigger's source selection, for the catch-up's bound, and that a failing catch-up leaves the chat path untouched.
