# Nyx Backend: Architectural Evolution

The history and design decisions behind the current backend. For the high-level "done / next" checklist, see `FUTURE.md` §1–3, 5.

## 1. Core Framework & Architecture

- [x] **Migrate to chi v5 + huma v2** (superseded the original Gin attempt). Stdlib-compatible `func(http.Handler) http.Handler` middleware chain on chi v5; declarative `huma.Operation{}` on huma v2 emits OpenAPI 3.1 from struct tags. REST contract preserved byte-for-byte (paths, methods, JSON envelopes) so the frontend, e2e suite, and CI are unaffected. See `backend/HUMA.md`.
- [x] **Clean Architecture** — `internal/{feed,user}/{model,repository,service,huma_handler}.go`. Cross-cutting infra in `internal/platform/{config,database,cache,auth,api}` and `internal/reqctx/`.
  ```
  backend/
  ├── cmd/api/                 # main.go: viper → DB → cache → domains → router → http.Server
  ├── internal/
  │   ├── middleware/          # chi middlewares (RequestID, RealIP, Recoverer, Prometheus, Logging, CORS, RateLimit)
  │   ├── feed/                # Feed domain — model, repository, service, huma_handler, *tests
  │   ├── user/                # User domain — model, repository, service, huma_handler, *tests
  │   ├── platform/            # config, database, cache, auth, api
  │   └── reqctx/              # Typed ctx values (auth claims, request id)
  ├── migrations/              # golang-migrate, applied on boot
  └── queries/                 # sqlc input (.sql)
  ```

## 2. Validation & Error Handling

- [x] **Struct-based validation** — `go-playground/validator` driven by struct tags on huma input/output types.
- [x] **Standardized JSON errors** — uniform envelope across handlers; central mapper in `internal/platform/api`.
- [x] **Domain error sentinels** — `feed.ErrNotFound`, `user.ErrInvalidCredentials`, `auth.ErrInvalidToken`, `auth.ErrExpiredToken`. Handlers translate to HTTP status; never string-compare in tests or call sites.
- [x] **Internal error messages never echo to clients** — `api.ClassifyAndLog(ctx, err, safeDetail)` logs the wrapped error with the request ID at `Warn` and returns the static `safeDetail`. Handlers and auth middleware call it instead of writing `err.Error()` into the response `details` field, so SQL fragments, bcrypt strings, and JWT parser errors stay off the wire.
- [x] **Semantic API Error Translators** — `internal/platform/pgerr.Translate` / `Map` reads `pgconn.PgError.Code` + `ConstraintName` and returns the matching domain sentinel (`user.ErrUsernameTaken` for `users_username_key`, `user.ErrRefreshTokenCollision` for `idx_refresh_tokens_token_hash`). `internal/platform/api.MapError(ctx, err, safeDetail)` is the single handler-layer funnel — every handler shrinks to one line on the error path, and unknown errors reuse `ClassifyAndLog` so internal error text never reaches the wire. `ErrUserAlreadyExists` was split from `ErrUsernameTaken` (status 409 stays, messages collapse); `ErrRefreshTokenCollision` maps to 500 (sha256 collisions are ~10⁻³⁸ per row). The email collision path was removed when email became optional.

## 3. Security & Authentication

- [x] **JWT auth** — `auth/jwt.go` issues `Bearer` tokens (HS256, 15m default via `JWT_ACCESS_TTL`); `middleware.NewAuth` / `NewHumaAuth` validate the `Authorization` header and store claims on `reqctx`. Algorithm pinning + issuer + audience + type claim guards (`type: "access"`) defend against alg-confusion and refresh-token-as-access attacks.
- [x] **User management** — `users` table with bcrypt-hashed passwords.
- [x] **Auth middleware** — write/delete routes require a valid Bearer token; read routes are public.
- [x] **Rate limiting** — token bucket middleware (`middleware/ratelimit.go`).
- [x] **CORS Hardening** — `middleware.NewCORS` reads `CORS_ALLOWED_ORIGINS` (default empty — deny-by-default); set a comma-separated origin list in production. Wildcard and explicit-allowlist modes are both supported and unit-tested. `Access-Control-Allow-Credentials` is intentionally never set: Bearer is a plain Authorization header (custom → preflight → backend allowlist = CSRF defence), so ACAC would only matter if cookies returned to the picture.
- [x] **Bearer-only auth transport** — `/api/login`, `/api/register`, `/api/refresh` return `{access_token, refresh_token, token_type: "Bearer", expires_at, user}` in the body. `/api/refresh` and `/api/logout` read the refresh token from the request body. The legacy cookie / `CookieConfig` plumbing is gone (`backend/internal/platform/auth/cookies.go` deleted; `COOKIE_*` viper bindings removed). Same wire contract works for SPA, iOS / Android native apps, Unity / Unreal game clients, and (after `POST /api/auth/exchange`) PSN / Xbox / Nintendo / Steam console clients.
- [x] **JWT Secret via Viper Config** — `auth.SetSecret(cfg.JWTSecret)` is called once in `main.go`; `auth/jwt.go` no longer reads `os.Getenv`. (Superseded by constructor injection — see below.)
- [x] **Constructor-injected JWT signing** — `auth.TokenService` interface + `auth.NewTokenService(secret []byte)` constructor hold the signing key in a private field. `main.go` builds one and threads it through the user service and auth middleware; the package-level `secret` / `SetSecret` are gone.
- [x] **Enforce non-default JWT secret at startup** — `config.Load()` and `auth.NewTokenService` both refuse the built-in default placeholder and any key shorter than `auth.MinSecretBytes` (32 bytes). Misconfiguration fails closed before the HTTP server starts.
- [x] **JWT Refresh Tokens** — opaque `refresh_tokens` table (`BIGSERIAL id`, `BYTEA token_hash` from `sha256`, `BIGINT family_id` self-referencing the original row, `replaced_by_id` self-FK). `crypto/rand` 32-byte tokens, base64url-encoded. Atomic rotation via a two-CTE statement; reuse of a revoked token revokes the entire family. `JWT_ACCESS_TTL` / `JWT_REFRESH_TTL` (defaults 15m / 168h). `POST /api/refresh` issues a new pair; `POST /api/logout` (auth-required) revokes the supplied token's family. `WWW-Authenticate: Bearer error="invalid_token", error_description="expired"` on the access-expired path so the frontend can reactively refresh without string-comparing error messages.
- [x] **Per-owner feed authorization** — `feeds.user_id` BIGINT (FK to `users.id`), every sqlc query filters `WHERE user_id = @user_id` (plain `=`, never `sqlc.narg` — the handler always has a user id now that `GET /api/feeds` is auth-required). `Repository` interface gains a `userID int` arg on `GetAll` / `Create` / `Update` / `Delete`; `Update` / `Delete` map `pgx.ErrNoRows` and `RowsAffected == 0` to the existing `feed.ErrNotFound` (single 404, no `ErrForbidden` — cross-owner writes are indistinguishable from missing ids to the caller). `userID` is read inside the service from `reqctx.UserIDFromContext`, never threaded by the handler. Cache keys include the user id (`feeds:u={id}:q=...`) and mutation invalidation uses `DeletePrefix("feeds:u={id}:")` so writes by user A never evict user B's cached page. Migration 000012 is the schema change; 000002's pre-seeded feed rows are reassigned to a `__pre_owner_scope_seed__` placeholder user inserted inline by the migration itself (production never hits that branch — real users register before any feed is created).

## 4. Database Layer

- [x] **Type-safe SQL** — `sqlc` over `pgx/v5` + `pgxpool`. SQL lives in `backend/queries/*.sql`; generated code in `internal/{feed,user}/db/` is regenerated via `make sqlc` and verified in CI via `make sqlc-diff`. See `backend/SQLC.md`.
- [x] **Transaction support** — pooled connections; complex flows use explicit `pgx.Tx` boundaries.
- [x] **Connection pooling** — pgxpool settings via viper (`MaxConns`, `MinConns`, `MaxConnLifetime`, `MaxConnIdleTime`).
- [x] **Index optimization** — `migrations/000006_add_feeds_indexes.sql`, `000007_add_feeds_description_trgm_index.sql` (pg_trgm for `ILIKE` search).
- [x] **Cache-aside** — Redis for `GET /api/feeds`. Keys: `feeds:q={query}:p={page}:s={size}`. Mutations call `DeletePrefix("feeds:")` (SCAN + UNLINK, non-blocking). Cache is best-effort: every call swallows errors with `log.Warn` and never fails the request.

## 5. Observability & Documentation

- [x] **OpenAPI 3.1** — generated from huma struct tags on each operation's Input/Output. UI at `/api/swagger` (Stoplight Elements); raw spec at `/api/swagger/doc.json` (and `doc.yaml`). Also committed as `api/openapi.json`, regenerated database-free via `cd backend && make openapi` and drift-checked in CI via `make openapi-diff`. See `backend/HUMA.md`.
- [x] **Prometheus metrics** — `/metrics` endpoint + `prometheus` middleware (request count, latency, status, in-flight).
- [x] **Contextual logging** — `context` threaded through every layer; request ID propagated from the `RequestID` middleware through `Logging` → services → repositories.
- [x] **Distributed Tracing (OTel)** — SDK initialised in `cmd/api/main.go` via `internal/platform/observability`. HTTP entry traced by `middleware.Tracing` (chi-native `otelhttp` with chi-route-template span names); service-layer spans in `feed.Service` and `user.Service`; pgx pool traced via internal `pgx.QueryTracer` (`observability/pgx.go`). Exporter: OTLP HTTP → Jaeger v2 (compose `jaeger` service, image `jaegertracing/jaeger:2.18.0`, UI on `:16686`). Default-off (`OTEL_ENABLED=false`) — every `tracer.Start` is a no-op and pgx skips its tracer callback when the global provider is noop. Sampling: `ParentBased(AlwaysOn)`; SDK honours `OTEL_TRACES_SAMPLER`. Scope intentionally narrow (HTTP + service + pgx) — repository and cache spans deliberately out of scope (pgx covers the SQL boundary, cache is best-effort noise). `trace_id` and `span_id` are added to the `Logging` middleware's per-request zerolog line whenever a valid span context is on the ctx.
  - **Frontend integration.** The W3C TraceContext + Baggage composite propagator installed on `otel` means inbound `traceparent` headers from upstream calls (the SPA's axios interceptor) are extracted automatically and the backend server span becomes a child span. `TestTracing_PropagatesTraceparentFromUpstream` (`backend/internal/middleware/tracing_test.go`) covers this path using `tracetest.NewSpanRecorder()`.
  - **Cache metrics.** `cache_operations_total{op,result}` in `internal/platform/cache/cache.go` records `hit`/`miss`/`error` per Get. `TestCacheMetrics` (`backend/internal/platform/cache/cache_test.go`) gathers via `prometheus.DefaultGatherer` and asserts both label permutations.

## 8. LLM Streaming Chat

- [x] **Provider abstraction** — `internal/llm.Provider` is the seam future features (summaries, semantic search) consume. Callback-based streaming (`Chat(ctx, req, onDelta) (*ChatUsage, error)`) keeps the wire format in the handler. Errors funnel through `internal/llm.ErrProviderUnavailable` / `ErrRateLimited` / `ErrInvalidInput` / `ErrContextCanceled`, registered with `api.RegisterSentinel` for the standard MapError path. See §9 for the OpenAI-compatible implementation.
- [x] **OpenAI-compatible client** — `internal/llm/openai.Client` uses `github.com/sashabaranov/go-openai` with `BaseURL` set from `LLM_BASE_URL`. The same client works against OpenAI's hosted endpoint (`https://api.openai.com/v1`) and any self-hosted vLLM server (`http://vllm.internal:8000/v1`) because vLLM exposes the identical `/v1/chat/completions` SSE wire contract. Streaming: `Stream=true` + `StreamOptions.IncludeUsage=true` so the trailing usage chunk arrives on the same stream. Errors mapped via `errors.As` on `*openai.APIError` (429 → rate-limited; ≥500 → provider-unavailable) and `*openai.RequestError` (network → provider-unavailable); context cancellation → `ErrContextCanceled`. Null Delta.Content frames (OpenAI's role-change frames) are skipped.
- [x] **Dedicated vLLM client** — `internal/llm/vllm.Client` implements `llm.Provider` against a self-hosted vLLM server via raw `net/http` + a hand-rolled SSE decoder. Selected via `LLM_PROVIDER=vllm`. Raw HTTP (not the SDK) so vLLM's slightly different error JSON and optional tool-call deldas don't have to be filtered through SDK-typed errors. Empty `LLM_API_KEY` allowed (vLLM without `--api-key` accepts any Authorization header). The client's `http.Transport.DialContext` re-runs the IP-class allowlist on every connection — closing the DNS-rebinding window that a startup `LookupIP` check would leave open. OTel span `llm.vllm.chat` with attributes `llm.provider="vllm"`, `llm.model`, `llm.messages`, `llm.max_tokens`, `llm.prompt_tokens`, `llm.completion_tokens`, `llm.total_tokens`. Compose: `docker compose --profile vllm up` brings up `vllm/vllm-openai:v0.6.3.post1` with Qwen2.5-3B-Instruct as the default model.
- [x] **`POST /api/chat` SSE endpoint** — `internal/chat.Handler.stream` writes `text/event-stream; charset=utf-8` with `X-Accel-Buffering: no` (defeats nginx ingress buffering), `Cache-Control: no-cache`, `Connection: keep-alive`. Wire format: `event: delta\ndata: {"delta":"..."}\n\n` per content chunk, `event: done\ndata: {"usage":{...}}\n\n` on completion, `data: [DONE]\n\n` terminator. Mid-stream upstream failure emits `event: error\ndata: {"error":"<safe static>","request_id":"..."}\n\n` then `[DONE]` — the HTTP status is already 200 because the SSE headers flushed before the error.
- [x] **Route mounted on chi, not huma** — huma v2 has no first-class SSE (response of unknown length, JSON schema can't capture the streaming shape). `chat.RegisterChatRoute(router, handler, tokens, limiter)` mounts the route directly on chi after the huma adapter wraps the router, so the route still runs through the standard middleware chain (RequestID → Recoverer → Prometheus → Logging → CORS → RateLimit → maxBodyBytes → NewAuth → UserRateLimiter). See `backend/HUMA.md` for the rationale.
- [x] **Server-only system prompt** — `LLM_SYSTEM_PROMPT` is prepended by `chat.Service.Chat` (defaults to a hard-coded feed-catalog prompt when empty). Clients cannot override it: any `role: "system"` message is rejected at `Service.Validate` with `ErrInvalidInput` → 400 envelope before any SSE bytes hit the wire.
- [x] **Per-user in-memory rate limiter** — `chat.NewUserRateLimiter(rate, burst)` is a token bucket keyed by `reqctx.UserIDFromContext`. Defaults from `cmd/api/main.go`: 5 streams/min, burst 3. Charged on stream-open (a single stream holds one slot regardless of duration). Background goroutine GCs buckets idle for over an hour on a 1-minute tick; stopped on shutdown. In-memory only — a horizontally-scaled deployment multiplies the cap by replica count, which is the right behaviour for a soft cap.
- [x] **Fail-closed config** — `LLM_ENABLED=true` requires non-empty `LLM_BASE_URL` / `LLM_MODEL` (and `LLM_API_KEY` when `LLM_PROVIDER=openai`); `LLM_API_KEY` is checked against a placeholder blocklist (`changeme`, `your-key`, `sk-xxx`, `xxx`, `test-key`) so a stray `.env` with a literal placeholder refuses to start. `LLM_PROVIDER` must be one of `{openai, vllm}`. `LLM_BASE_URL` is scheme-validated (http/https only), userinfo is rejected, and the host refuses loopback / RFC1918 / link-local / multicast / unspecified unless `LLM_ALLOW_PRIVATE_URL=true` — the vLLM client's `DialContext` re-runs the IP-class check on every dial so DNS rebinding can't swap a public hostname's answer for a private IP between startup and the first dial. Durations (`LLM_TIMEOUT`, `LLM_MAX_STREAM_DURATION`) parsed at startup.
- [x] **Safe-error-detail contract preserved** — handlers never copy `err.Error()` into the wire. Validation errors → 400 JSON envelope before SSE headers. Mid-stream errors → trailing `event: error` with a static safe message + request ID; the underlying error is logged at Warn via `api.ClassifyAndLog` for operator correlation.

## 9. Provider Abstraction (seam for future features)

- [x] **Interface** — `internal/llm.Provider.Chat(ctx, req, onDelta) (*ChatUsage, error)`. `onDelta` is invoked once per non-empty content chunk with `(delta, nil)`, and once on the trailing usage chunk with `("", *ChatUsage)`. Returning a non-nil error from `onDelta` aborts the read and surfaces to the caller — used by the chat handler to propagate client-disconnect signals from the SSE writer's `Flush()` error.
- [x] **Embed** — `internal/llm.Provider.Embed(ctx, EmbedRequest) ([][]float32, error)` (added in RAG §10). Same failover router wraps embeddings as chat — the primary `/v1/embeddings` endpoint inherits the chat client's SSRF guard (the vLLM client reuses `newHTTPClient`'s per-dial IP-class allowlist; the OpenAI client goes through the SDK's standard transport). NO `/v1/models` probe for embeddings — the call result IS the liveness signal, so a probe would be wasted round-trip. Both openai + vllm clients implement it; chat tests panic on Embed calls so a future regression that reaches past the rag facade catches itself.
- [x] **Reusable across features** — the abstraction was designed to support the chat feature, but the same shape (validated messages, provider call, usage capture) extends naturally to: per-feed summary generation, semantic re-ranking of search results, "explain why this feed entry matched" tool calls. Each future feature adds its own domain package under `internal/{feature}/` and reuses `internal/llm/openai.Client`.
- [x] **LLM failover router** — `internal/llm.Router` wraps two `ProviderSlot`s with a per-request `GET /v1/models` probe (default 2s, capped by `LLM_PROBE_TIMEOUT`) and one-shot mid-stream failover. New env: `LLM_FALLBACK_BASE_URL`, `LLM_FALLBACK_API_KEY`, `LLM_FALLBACK_MODEL`. `LLM_PROVIDER` is the primary preference; the fallback's provider type is implicit (the opposite — today only openai ↔ vllm). New sentinel `llm.ErrAllProvidersFailed` (502, joins `ErrProviderUnavailable` so existing error-chain checks keep working). `ChatRequest.OnNote` plumbs the failover notice through `chat.Service.Chat` to a new `event: note` SSE frame the SPA renders as a "continued on {provider}" line. Single-provider deployments skip the Router entirely (zero probe cost); dual-provider deployments accept ~50–200ms probe as the price of failover.

## 10. RAG over feeds

- [x] **pgvector in Postgres** — `pgvector/pgvector:pg17-alpine` is the dev image (compose `db` service). `CREATE EXTENSION IF NOT EXISTS vector` is the first statement of migration 000014; a vanilla `postgres:17` image fails the migration with a clear "extension 'vector' is not available" rather than a cryptic "type vector does not exist". The codec is registered on every new pgx connection via `poolCfg.AfterConnect` → `pgxvec.RegisterTypes` so the `vector(N)` column round-trips cleanly.
- [x] **`feed_embeddings` table** — one row per feed. `embedding vector(1536)` matches `EMBEDDING_DIMENSIONS` (default 1536 = `text-embedding-3-small`). `user_id` denormalised so retrieval is one indexed range scan, no JOIN; the retriever still JOINs `feeds` and applies `user_id` on both sides as defence-in-depth. `content_hash` is sha256 of `chunk_text`; the Indexer SELECTs it before calling the Embed API, so a no-op UpdateFeed costs one sha256 and zero API calls. HNSW index (`vector_cosine_ops`) on the embedding column; pgvector's WHERE-filtered HNSW serves the per-user `ORDER BY <=> LIMIT K`.
- [x] **`internal/rag` package** — `Embedder` (chunk_text + sha256 + llm.Provider.Embed), `Indexer` (writes feed_embeddings; skip-on-no-op via content_hash), `Retriever` (top-K semantic lookup, user-scoped), `Service` (chat-side orchestrator: embed query → retrieve → render context block truncated at `RAG_MAX_CONTEXT_CHARS` → lazy backfill via `sync.Map` + `sync.Once` per user). `RetrieverIface` lets chat service tests stub retrieval without a database. `Pool` is an interface (pgxpool.Pool + pgxmock both satisfy) for unit tests.
- [x] **Embed-on-write hook in feed domain** — `feed.EmbeddingIndexer` interface (declared in feed, satisfied by rag.Indexer structurally) keeps the dependency one-way (rag → feed.Feed). Hooks on Create / Update / Delete are best-effort: a failed embed logs a warn and never fails the write. `feed.NoopEmbeddingIndexer{}` for LLM-disabled deployments.
- [x] **`rag: true` on POST /api/chat** — the chat service injects the rendered context as a NEW user-role message immediately after the last user turn (matches the standard "document Q&A" prompt shape; keeps the validator's view of the request unchanged). Retrieval failure logs + continues without context — the chat never fails because RAG is sick. Backfill is fire-and-forget with a detached 30s ctx so the chat request returning doesn't kill it. A `sync.Map` + `sync.Once` per userID serialises the backfill (100 concurrent goroutines for the same user → exactly one backfill).
- [x] **Operator runbook for embedding dim drift** — `cmd/api/main.go`'s `warnEmbeddingDimMismatch` queries `pg_attribute.atttypmod` for the live `feed_embeddings.embedding` column and logs a loud warning (NOT fail-closed) when it disagrees with `EMBEDDING_DIMENSIONS`. Operators switching to a different-dim model write a new migration that drops + recreates the column; pgvector does not support in-place `ALTER COLUMN TYPE` for vector dim changes. After the schema migration, the lazy backfill (or a `TRUNCATE feed_embeddings` + reload) re-embeds.
- [x] **Cross-layer test coverage** — `internal/rag/{embedder,indexer,retriever,service}_test.go` cover the unit-test surface (the pgxmock retriever test pins the cross-user-leak canary via a regex that requires both `fe.user_id` + `f.user_id` + `deleted_at IS NULL`). `internal/rag/integration_test.go` is the pgvector-backed smoke test (skipped without `DB_URL` or with `SKIP_CONTAINERS=true`). The feed service has `stubIndexer` + 5 indexer-hook tests in `service_test.go`. The chat service has 7 RAG-paths tests in `service_test.go` (off / on / empty result / retrieve error / no userID / nil ragSvc / history preserved). Frontend `chatService.test.ts` + `chatStore.test.ts` + `ChatPanel.test.tsx` cover the toggle persistence + body shape + UI rendering.

## 11. MCP server for feeds

- [x] **Architecture** — `internal/mcp/` consumes `feed.Service` via its public surface (`GetFeeds` / `GetFeedByID` / `CreateFeed` / `UpdateFeed` / `DeleteFeed`). The mcp layer never touches a repository; all per-owner scoping is enforced inside `feed.Service` via the auth-stamped context that chi's `middleware.NewAuth` writes before the route handler runs. The route is mounted on chi (bypassing huma) for the same reason chat is — Streamable HTTP carries a JSON-RPC envelope whose body is unknown shape to huma's schema generator, and SSE response flushing needs direct http.Handler control. See `backend/HUMA.md` "Streaming endpoints" for the full rationale.
- [x] **Why `mark3labs/mcp-go`, not the official SDK** — the official `github.com/modelcontextprotocol/go-sdk` ships only `StdioTransport` and `CommandTransport` (no HTTP) per its README. `mark3labs/mcp-go` ships `StreamableHTTPServer` (implements `http.Handler`) plus stateful/stateless toggles, CORS helpers, and recovery. We pin `v1.1.0`. A future migration to the official SDK becomes attractive once it ships an HTTP transport — at that point the seam is small (replace `StreamableHTTPServer` with the official HTTP-binding).
- [x] **Transport** — Streamable HTTP at `MCP_PATH` (default `/mcp`). Stateless mode (`server.WithStateLess(true)`) — every request carries all state in the JSON-RPC envelope; the JWT subject is the only session identifier. POST/GET/DELETE all accepted by the mcp-go server per the spec. `server.WithDisableLocalhostProtection(true)` because the route sits behind chi (the trust boundary); the mcp-go localhost guard would block browser clients running on localhost, which is the wrong default for an HTTP-fronted MCP server.
- [x] **Auth** — `middleware.NewAuth(tokens)` runs before the route handler (same as `/api/chat`). Reads `Authorization: Bearer <jwt>` (RFC 6750), validates against `auth.TokenService`, stamps `reqctx.WithUserID` + `WithUsername` on the request context. The mcp service reads `reqctx.UserIDFromContext(ctx)` per call — never threads userID as a tool argument. Cross-owner reads map to `feed.ErrNotFound` (single sentinel, no existence leak) — same contract as the REST surface. A defensive `userID == 0` guard in each write handler fails closed (returns `mcp.ErrNotFound`) so a future route-ordering regression cannot let an unauthenticated request mutate state.
- [x] **Tool surface** — five tools, snake_case per MCP convention:
  - `list_feeds(query?, page?, page_size?, order?) → {data, page, page_size, total, has_more}` — same envelope as `GET /api/feeds`; `page_size` hard-clamped to 100 server-side.
  - `get_feed(id) → Feed | error` — `id >= 1`; error when missing OR cross-owner.
  - `create_feed(title, description?) → Feed` — title `1..100` chars, description `0..1000`; server stamps id/timestamps.
  - `update_feed(id, title, description?) → Feed | error` — same constraints; error when missing OR cross-owner.
  - `delete_feed(id) → {deleted:true, id} | error` — soft-delete; error when missing OR cross-owner.
- [x] **Error mapping** — `feed.ErrNotFound` → `mcp.ErrNotFound`; everything else → `mcp.ErrInternal` via `api.ClassifyAndLog(ctx, err, safeDetail)` (logs the original with request ID, never copies `err.Error()` to the wire). mcp-go surfaces tool-level errors as `{jsonrpc, id, error: {code, message}}` envelopes (HTTP 200). JSON-RPC code constants: `-32601` MethodNotFound, `-32602` InvalidParams, `-32603` InternalError, plus our application-level `-32004` (not used by mcp-go automatically — we surface our `ErrNotFound` as `-32603` today, which is the spec-correct fallback for tool-level failures; revisit if the MCP spec adds a dedicated "resource not found" tool error code). Rate-limit short-circuit returns a synthesised JSON-RPC error envelope at HTTP 429 with code `-32005`.
- [x] **Rate limiting** — per-user token bucket (in-memory, no Redis). Default 60 calls/min sustained (1 token/sec refill) with burst 20 — ten times the chat default because MCP tool calls are cheap short-lived RPCs, not long-lived streams. `Retry-After: 60` header on 429. Cost trade-off documented in `internal/mcp/ratelimit.go`.
- [x] **Default-off toggle** — `MCP_ENABLED=false` (the default) means no route mounted, no mcp-go server built, no per-user limiter running — deployments without external agents pay zero allocation. Cross-field validation (only runs when enabled): `MCP_PATH` must start with `/` and contain no `?`/`#`; `MCP_MAX_BODY_BYTES` must be in `[1024, 1048576]`. `validateMCPConfig` fails the boot on misconfiguration (same shape as `validateLLMConfig`).
- [x] **Body cap** — outer router-level 1 MiB cap fires first (cmd/api/main.go's `maxBodyBytesLimit`); inner `MCP_MAX_BODY_BYTES` (default 64 KiB) wraps `r.Body` in `http.MaxBytesReader` inside the mcp Handler so an oversized JSON-RPC payload fails fast. Matches chat's `MaxBodyBytes = 64 KiB`.
- [x] **Tracing** — every tool call opens a span `mcp.dispatch.<tool>` (kind=internal). Noop when `OTEL_ENABLED=false`. The mcp-go server itself doesn't add HTTP-level spans; the chi-level `middleware.Tracing` span is the parent.
- [x] **OpenAPI artifact** — MCP is chi-direct, not huma-registered, so it does NOT appear in `api/openapi.json`. Clients discover the tool surface via the standard MCP `initialize` / `tools/list` handshake.
- [x] **Test coverage** — `internal/mcp/service_test.go` (10 unit tests covering page-size clamp, sort default, userID stamping, sentinel mapping, fail-closed on missing userID, structured-content encoding) + `internal/mcp/handler_test.go` (10 HTTP tests covering auth gate, initialize handshake, tools/list, tools/call happy path, not-found tool error, per-owner isolation, unknown-tool rejection, body-too-large rejection, rate-limit 429, per-user rate-limit isolation). 77.5% coverage (above the 70% gate).
- [x] **Manual smoke test** — `MCP_ENABLED=true go run ./cmd/api`, mint a JWT via `/api/login`, then `curl -X POST http://localhost:8080/mcp -H 'Authorization: Bearer $TOKEN' -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{...}}'`. The official `@modelcontextprotocol/inspector` (`npx @modelcontextprotocol/inspector`) is the recommended visual client — connect to `http://localhost:8080/mcp` with the JWT in the auth field.
- [x] **Roadmap notes** — this is the first new domain on the chi-direct path since chat landed. Future MCP primitives (workspace addition, elicit, sampling) and additional domains (e.g. user-account tools, chat tools) plug in via the same `internal/<feature>/` shape.
